# Vendor Revenue and Peak Demand Analysis Using Hadoop MapReduce

## 📌 Project Overview

This project implements a **Big Data analytics solution using Apache Hadoop MapReduce** to analyze NYC taxi trip data.

The project focuses on two important analytical tasks:

1. **Vendor Revenue Analysis** – analyzing taxi trip revenue based on different vendors.
2. **Hourly Peak Demand Analysis** – identifying the hours with the highest taxi demand.

The project demonstrates how large-scale transportation data can be processed efficiently using the **MapReduce programming model**, with Java-based Mapper, Reducer, and Driver implementations.

---

## 🎯 Objectives

The main objectives of this project are:

* Process large-scale NYC taxi trip data using Hadoop MapReduce.

# 🔹 Analysis 1: Vendor Revenue Analysis

## Objective

The first MapReduce job analyzes the revenue associated with different taxi vendors.

The Mapper extracts the required vendor and revenue information from each valid taxi trip record and emits them as key-value pairs.

The Reducer then aggregates the revenue values associated with each vendor.

### MapReduce Flow

```text
Input NYC Taxi Data
        ↓
      Mapper
        ↓
Vendor → Revenue
        ↓
 Shuffle & Sort
        ↓
     Reducer
        ↓
Vendor → Total Revenue
```

### Example

A simplified input might contain:

```text
Vendor A, 20.50
Vendor B, 15.75
Vendor A, 30.00
Vendor B, 25.25
```

The Mapper generates:

```text
Vendor A → 20.50
Vendor B → 15.75
Vendor A → 30.00
Vendor B → 25.25
```

The Reducer aggregates the values:

```text
Vendor A → 50.50
Vendor B → 41.00
```

This allows the overall revenue contribution of each vendor to be compared.

## 📁 Vendor Revenue Implementation

The Java implementation contains:

```text
VendorRevenueMapper.java
VendorRevenueReducer.java
VendorRevenueDriver.java
```

### Mapper

The Mapper:

* Reads each input record.
* Parses the required fields.
* Extracts the vendor identifier.
* Extracts the relevant revenue value.
* Emits the vendor as the key and revenue as the value.

### Reducer

The Reducer:

* Receives all revenue values associated with a vendor.
* Aggregates the values.
* Produces the total revenue for each vendor.

### Driver

The Driver:

* Configures the Hadoop MapReduce job.
* Specifies the Mapper class.
* Specifies the Reducer class.
* Defines input and output paths.
* Configures the required input/output data types.
* Executes the MapReduce job.

# 🔹 Analysis 2: Hourly Peak Demand Analysis

## Objective

The second MapReduce job analyzes taxi demand by hour.

The purpose is to identify the hours during which the number of taxi trips is highest.

This can help identify:

* Peak transportation periods
* High-demand hours
* Traffic patterns
* Potential resource requirements
* Periods requiring increased taxi availability

### MapReduce Flow

```text
Input NYC Taxi Data
        ↓
      Mapper
        ↓
Hour → 1
        ↓
 Shuffle & Sort
        ↓
     Reducer
        ↓
Hour → Total Trips
        ↓
Identify Peak Demand
```

### Example

If the Mapper generates:

```text
08 → 1
08 → 1
09 → 1
09 → 1
09 → 1
10 → 1
```

The Reducer aggregates the counts:

```text
08 → 2
09 → 3
10 → 1
```

Therefore:

```text
09 → Peak Demand
```

---

## 📁 Peak Demand Implementation

The Java implementation contains:

```text
PeakDemandMapper.java
PeakDemandReducer.java
PeakDemandDriver.java
```

### Mapper

The Mapper:

* Reads each taxi trip record.
* Extracts the relevant pickup-time information.
* Determines the hour.
* Emits the hour as the key.
* Emits a count of `1` for each valid trip.

### Reducer

The Reducer:

* Receives all counts belonging to each hour.
* Adds the counts.
* Produces the total number of trips for each hour.

### Driver

The Driver:

* Configures the Hadoop job.
* Sets the Mapper and Reducer.
* Defines input and output paths.
* Configures Hadoop data types.
* Executes the job.

# 💰 3. Run Vendor Revenue Analysis



## ⭐ Summary

This project demonstrates how **Hadoop MapReduce can be used to process NYC taxi data at scale** and extract meaningful insights through distributed computation.

The two primary analyses are:

> **Vendor Revenue Analysis** — determines revenue aggregated by taxi vendor.

The project provides a complete workflow from **raw data → HDFS → Mapper → Shuffle & Sort → Reducer → analytical results**.
